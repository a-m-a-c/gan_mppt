# SPS5162X current-source interface

The connected instrument identifies as a Siglent **SPS5162X**, serial
`SPS62ABD7R0750`, firmware `3.1.1.8R1`. USB resource:

```text
USB0::0xF4EC::0x1452::SPS62ABD7R0750::INSTR
```

The driver uses PyVISA and the NI-VISA backend already installed on this PC.
PyVISA is locked in `tools/uv.lock`; use `uv sync --project tools --locked`
on another checkout. A VISA backend must also be installed on another PC.
An explicit `--resource` accepts VISA TCPIP resources as well, but LAN has
not been bench-tested here.

## Read or change a setting

```powershell
uv run --project tools --locked python tools/sps5162x.py --list
uv run --project tools --locked python tools/sps5162x.py status
uv run --project tools --locked python tools/sps5162x.py set-current 4
uv run --project tools --locked python tools/sps5162x.py set-voltage 35
uv run --project tools --locked python tools/sps5162x.py output off
```

The default bench limits are **0–8 A** and **0–35 V**, with 1 mA / 1 mV setting
resolution. Out-of-range and nonfinite inputs are rejected before sending.
Setters wait for command completion, check the SCPI event status, and verify
the programmed value by querying it back. `status` reports programmed limits,
output state, measured voltage/current/power, and the reported CV/CC state.

Opening or closing a driver session does not change output state. A direct
`output on` command deliberately leaves output on after the CLI exits;
`output off` turns it off. Enabling is refused if the existing programmed
limits exceed the bench limits, instrument LIST mode is active, voltage or
current is externally controlled, or output ON/OFF delays are nonzero.

## Python API

```python
from sps5162x import SPS5162X

with SPS5162X.open() as supply:
    supply.set_current_limit(4.0)  # Does not enable output.
    print(supply.readback())
```

Available methods: `open(resource=None)`, `set_current_limit(amps)`,
`set_voltage_limit(volts)`, `set_output(enabled)`, `readback()`, `close()`.
`open()` checks `*IDN?` and refuses a different instrument model. It chooses
the sole matching USB supply; specify a resource if more than one is present.

## Measurement 5: five-minute available-current ramp

With the dark panel in parallel, changing the supply's CC limit changes the
available current of the emulated solar source. The commands describe current
in amperes, not calibrated irradiance in W/m². The load determines whether the
supply actually operates in CC or CV; programming 8 A does not force 8 A into
an unloaded output.

Disconnect the bench website from COM6, connect the supply USB and MCU UART,
and use the normal channel A measurement setup (dark reference panel in
parallel with the supply, converter output connected to the test battery).
Run this single command from the repository root:

```powershell
uv run --project tools --locked python tools/measure_mppt_profile.py --port COM6
```

This **starts active MPPT on channel A and enables the supply output**.
`mode_measure` selects **600 kHz** on entry, with dynamic frequency disabled,
and restores the previous channel A frequency on exit. Flash the updated
firmware before the next run; the UART capture does not report frequency.
Updated firmware is also required for the startup gate. The script checks
the gated-capture flag before enabling the supply; older firmware is refused.
The combined script:

1. Confirms supply output off, sends MCU STOP and starts `mode_measure` with PWM held off.
2. Waits for valid channel A samples, then records a 2 s baseline with supply and PWM off.
3. Sets 35 V compliance and **0.5 A**, enables output, and verifies the nonzero
   setting before sending `measure_start`. Firmware retains its stable/reachable
   startup checks. The source then rises gradually **0.5 -> 8 A over 300 s**.
4. Holds 8 A for **5 s**, switches the supply off, records a 2 s tail, then sends MCU STOP.
5. Generates plots after shutdown. Nominal capture is 2 + 300 + 5 + 2 = **309 s**
   (5 min 9 s), plus setup overhead.

The ramp changes the setpoint every **0.5 s**: (8 - 0.5)/300 = 0.025 A/s,
so commands increase by 12 or 13 mA after supply-resolution rounding. There are
601 targets including both endpoints. This is a fine staircase approximation
to a gradual ramp, not a native analog ramp. The zero-current baseline remains
supply-OFF. A changing source can affect P&O decisions; compare the result with
the separately characterized MPP path rather than assuming convergence.

This change is in the Python schedule only; no new firmware flash is required
if the existing gated measurement firmware is already installed. Each invocation
creates a new timestamped folder. Existing `captures/measure_5` and other captures
are not modified, even if the new run fails.

Firmware requires Vin's startup target `0.8 × Vin` to exceed
`Vbus × (1 − 0.70) + 0.5 V`, and Vin to remain within a 0.2 V band for 2 s.
For example, at 45 V bus the seed must be at least 14 V, requiring
Vin >= 17.5 V. The 0.5 V headroom and 0.2 V settling band are bench assumptions.
If MPPT has not begun within 30 s of the first verified nonzero setting,
the script aborts and requests shutdown. Custom profiles starting at 0 A
remain gated until a nonzero setting is verified.

The MCU `measure` opcode (0x0D) now starts capture only. `measure_start`
(0x11, no payload) releases startup, after valid streaming has begun.
`measure.py` sends it automatically; the combined script defers it until
the source is ready. Non-IV MPM1 records use bit 6 for gated-start support
and bit 7 for start accepted; IV records keep their existing meanings.
`run.json` logs start-request, acceptance and first-switching times; the
recorder logs the UART start-command time in `measure.json`.

The default ramp can also be specified explicitly:

```powershell
uv run --project tools --locked python tools/measure_mppt_profile.py --port COM6 --ramp 0.5 8 --duration 300 --interval 0.5 --voltage 35 --pre-seconds 2 --final-hold 5 --post-seconds 2
```

Everything is saved in **one** `captures/<timestamp>_measure_mppt_profile/` folder:

- `measure.csv`, `measure.bin`, `measure.json`: MCU samples, raw UART and capture metadata.
- `measure.svg`, `measure_dots.svg`: voltage, current, power and duty against MCU time;
  the second SVG has small dots and no connecting lines.
- `profile.csv`, `summary.json`, `profile.svg`: source commands/readbacks, timing and output shutdown status.
- `trajectory.svg`: channel A input current versus voltage, coloured by MCU time,
  with maximum sampled input power annotated. Display is capped at 20,000 points;
  peak selection uses all active samples and the complete CSV is retained.
- `run.json`: overall completion, errors, data quality and references to both logs.

The source log times and MCU `t_host_s` use the same host monotonic origin.
The MCU's `t_s` remains its own acquisition clock. UART arrival and sequential
VISA queries are not simultaneous ADC samples or hardware-triggered synchronization.
The reference MPP path still needs separate source characterization; maximum
sampled power alone does not measure MPPT tracking efficiency.

MCU faults, unexpected capture termination and source failures abort the run;
Ctrl+C also requests MCU STOP and supply output off, preserving partial logs.
`run.json` records shutdown confirmation. Completion requires an END record,
no reported fault/restoration error, and samples with PWM switching. Gaps,
CRC errors and firmware acquisition counters are reported separately as data quality.

## Measurement 5: 100 mV P&O comparison

The measurement-mode P&O voltage step is now 100 mV (formerly 50 mV).
PI gains, P&O cadence, arrival tolerance, startup and protections are unchanged.
Reflash with **Build & Flash Release** before collecting the new comparison.
No hardware readback of the P&O step is present in the capture protocol.

Disconnect the GUI from COM6, then run from the repository root:

```powershell
uv run --project tools --locked python tools/measure_mppt_profile.py --port COM6 --profile tools/profiles/mppt_low_current.csv --final-hold 60
```

This enables the supply and active MPPT: 1 A at 0 s, 2 A at 60 s, 4 A at
120 s, then 60 s at 4 A. The 60 s observation windows are a bench-test choice,
not a guarantee of convergence. Total capture is approximately
2 + 120 + 60 + 2 = 184 s plus setup and plotting. MPPT stays active between
plateaus; this tests response to changing current as well as low-current tracking.
Each run creates a new timestamped folder, retaining all previous measurements.
Compare the final five seconds of each plateau and its full settling trace with
the earlier 50 mV staircase and the reference MPP points.

After inspecting the fixed-current result, repeat the same five-minute ramp:

```powershell
uv run --project tools --locked python tools/measure_mppt_profile.py --port COM6
```

The ramp remains 0.5 to 8 A over 300 s, plus baseline/final hold/tail. This is
a step-size experiment; no power averaging or P&O decision changes are included.

## Supply-only profiles

For repeated fixed-current IV sweeps and the measurement-5 reference MPP path,
see [CHARACTERISE_IV.md](CHARACTERISE_IV.md). `characterise_iv.py` saves combined
raw/settled CSVs, per-branch reference maxima, and all curves on one V–I plane.
Its live mode enables the source; offline replotting and mock tests do not.

To run only the current-limit profile without MCU capture:

```powershell
uv run --project tools --locked python tools/current_profile.py --profile tools/profiles/irradiance_staircase.csv --final-hold 20 --voltage 35
uv run --project tools --locked python tools/current_profile.py --ramp 0.5 8 --duration 300 --interval 0.5 --voltage 35
```

For changes up and down, edit the example's `time_s,current_a` columns:

```powershell
uv run --project tools --locked python tools/current_profile.py --profile tools/profiles/irradiance_steps.csv --voltage 35
```

The whole profile is validated before changing output. The runner turns output
off, programs voltage and the first current limit, enables output, and applies
targets at their scheduled host times. It holds the last target for 1 s by
default, then turns output off. Errors and Ctrl+C also attempt shutdown; the
summary explicitly records whether output-off was confirmed. There is no
automatic retry/re-enable after a communication failure. Communication loss
can prevent software shutdown; the driver does not claim an instrument-side
watchdog.

```python
from pathlib import Path
from sps5162x import SPS5162X
from current_profile import CurrentStep, run_current_profile

with SPS5162X.open() as supply:
    result = run_current_profile(
        supply,
        [CurrentStep(0, 1.0), CurrentStep(5, 4.0), CurrentStep(10, 8.0)],
        voltage_limit_v=35.0,
        output_dir=Path("captures"),
    )
```

Each run writes `captures/<timestamp>_current_profile/`:

- `profile.csv`: scheduled time, actual command start, setpoint verification,
  readback completion, UTC timestamps, requested/programmed current, measured
  current/voltage/power, output state and CV/CC indication.
- `summary.json`: instrument identity, requested profile, completion/error and
  shutdown status. Partial files survive a failed or interrupted run.
- `profile.svg`: commanded current limit versus measured current, and voltage.

VISA queries are sequential host operations, not synchronized instrument
samples. The default 0.5 s lateness limit aborts a substantially late profile;
use the recorded command/readback times rather than assuming exact transitions.
`current_profile.py` controls the supply only. Use `measure_mppt_profile.py`
above to start MPPT and capture both together. Both tools use the same driver
and profile runner; the combined script defaults to a 20 s final hold, while
the supply-only CLI retains its 1 s hold.

## Bench verification, 30 October 2026

The user disconnected the supply from the MPPT system for testing. The driver
was tested on the identified USB instrument:

- Current limits 0, 0.001, 0.1, 0.5, 1, 2, 4 and 8 A were accepted and read back.
- Two output-enabled 0–8 A limit profiles ran at **2 V**, with 500 ms and
  250 ms command spacing. Both completed and confirmed output off.
- The 250 ms profile recorded 17 points, maximum command lateness 85.4 ms
  (including output-enable/preflight time) and measured voltage up to 1.997638 V.
- Original **35 V / 8 A** settings were restored, with output **off**.

Evidence: `captures/20261030-162720-282840_sps5162x_driver_test/`.
These were unloaded tests: they verify communications, setpoints, timing logs
and output switching, not loaded CC regulation or an MPPT irradiance response.

SCPI source: [SPS5000X user manual and programming guide](https://www.siglenteu.com/download/10688/),
pages 80–91. PyVISA API: [official resource documentation](https://pyvisa.readthedocs.io/en/stable/api/resources.html).
